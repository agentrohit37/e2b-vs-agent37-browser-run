# Billing & limits

> E2B plans, limits, and usage-based pricing. Covers the Hobby, Pro, and Enterprise plan table (max continuous runtime, concurrent sandboxes, vCPU, memory, disk), API rate limits, and how per-second compute billing works.

E2B uses [usage-based pricing](#usage-based-pricing) - you pay only for what you use. New users receive \$100 in free credits to get started.

[Manage billing in console](https://console.e2b.dev/?tab=billing)

Max continuous runtime is the time a sandbox can run **without being paused**, not a cap on how long a sandbox can exist. ## API rate limits

E2B applies rate limits to API requests. The following default limits are in **requests per second, per project, per endpoint**:

| Endpoint | Hobby | Pro | Enterprise |
| :- | -: | -: | -: |
| [`GET /sandboxes`](https://docs.e2b.dev/api-reference/sandboxes/list-sandboxes) | 10 | 20 | Custom |
| [`GET /v2/sandboxes`](https://docs.e2b.dev/api-reference/sandboxes/list-sandboxes-v2) | 10 | 20 | Custom |
| [`GET /sandboxes/metrics`](https://docs.e2b.dev/api-reference/sandboxes/list-sandbox-metrics) | 10 | 20 | Custom |
| [`GET /snapshots`](https://docs.e2b.dev/api-reference/sandboxes/list-snapshots) | 10 | 20 | Custom |
| [`GET /templates`](https://docs.e2b.dev/api-reference/templates/list-templates) | 10 | 20 | Custom |
| [`GET /v2/templates`](https://docs.e2b.dev/api-reference/templates/list-templates-v2) | 10 | 20 | Custom |
| [`GET /templates/{templateID}`](https://docs.e2b.dev/api-reference/templates/get-template) | 10 | 20 | Custom |
| [`GET /templates/{templateID}/tags`](https://docs.e2b.dev/api-reference/tags/list-template-tags) | 10 | 20 | Custom |
| [`GET /api-keys`](https://docs.e2b.dev/api-key) | 10 | 20 | Custom |
| [`GET /volumes`](https://docs.e2b.dev/api-reference/volumes/list-team-volumes) | 10 | 20 | Custom |
| [`GET /secrets`](https://docs.e2b.dev/api-reference/secrets/list-secrets) | 10 | 20 | Custom |

> [!NOTE]
>
> Enterprise plans come with API rate limits sized to your workload. [Book a call](https://e2b.dev/contact) with our team or contact us at [enterprise@e2b.dev](mailto:enterprise@e2b.dev) to discuss your limits.

You share each endpoint's limit across all API keys and clients in your [project](https://docs.e2b.dev/projects.md). Requests to one endpoint do not consume another endpoint's allowance. For endpoints with a path parameter, such as `/templates/{templateID}`, requests for different template IDs share the same allowance.

These limits include requests made through the SDKs and CLI. Each request for a page of results counts toward the limit.

### Exceeding a limit

If you exceed a limit, you receive an HTTP `429 Too Many Requests` response with a `Retry-After` header.

Starting with version **2.49.1**, the E2B JavaScript and Python SDKs automatically retry these requests using the `Retry-After` delay.

If you handle retries yourself, wait the number of seconds in `Retry-After` before retrying the request.

### Requesting a higher limit

To request a higher API rate limit, contact [support@e2b.dev](mailto:support@e2b.dev). For custom limits on the Enterprise plan, [contact sales](mailto:enterprise@e2b.dev).

## Usage-based pricing

You pay per second for compute resources while your sandbox is running.

Upgrading to the Pro tier does not grant additional credits. It only increases the limits available to your project (such as concurrent sandboxes, continuous runtime, and resource ceilings).

### Compute costs

Use the [usage cost calculator](https://e2b.dev/pricing#:~:text=Usage%20Cost%20Calculator) on our pricing page to estimate costs for your specific configuration.

### Customizing compute resources

You can customize allocated CPU and RAM when building custom templates by specifying `cpuCount` and `memoryMB` in the build configuration.

```js JavaScript & TypeScript theme={"theme":"css-variables"}
import { Template, defaultBuildLogger } from 'e2b'

await Template.build(template, 'my-template', {
  cpuCount: 8,
  memoryMB: 4096,
  onBuildLogs: defaultBuildLogger(),
})
```

```python Python theme={"theme":"css-variables"}
from e2b import Template, default_build_logger

Template.build(
    template,
    'my-template',
    cpu_count=8,
    memory_mb=4096,
    on_build_logs=default_build_logger(),
)
```

See [template quickstart](https://docs.e2b.dev/template/quickstart.md) for more details on building custom templates.

> [!NOTE]
>
> Need higher CPU or RAM limits? Contact [support@e2b.dev](mailto:support@e2b.dev) for more information.

## FAQ

> [accordion] When am I charged?
>
> Automatically at the start of the month for the previous month's usage.

> [accordion] What happens when I run out of credits?
>
> If you have no payment method, every project in your [workspace](https://docs.e2b.dev/workspaces.md#billing) is blocked shortly afterwards. Add a payment method to continue using E2B.

> [accordion] Can I set spending limits?
>
> Yes, you can set spending limits on the [budget page](https://console.e2b.dev/?tab=budget) in your dashboard.

> [accordion] How do I optimize costs?
>
> * **Enable auto-pause** - Automatically pause sandboxes after a period of inactivity to stop compute billing while preserving state
> * **Pause sandboxes when idle** - Use `sbx.pause()` to stop compute billing while keeping state available for later
> * **Kill sandboxes you no longer need** - Use `sbx.kill()` to stop billing and release resources permanently
> * **Allocate only what you need** - Start with default resources (2 vCPU, 512 MiB RAM) and increase only if necessary
> * **Monitor actively running sandboxes** - Use the [CLI](https://docs.e2b.dev/cli/list-sandboxes.md) or [console](https://console.e2b.dev/?tab=usage) to track active sandboxes
> * **Use lifecycle events** - Set up [webhooks](https://docs.e2b.dev/sandbox/lifecycle-events-webhooks.md) to get notified when sandboxes are created

> [accordion] Do I pay for compute on stopped sandboxes?
>
> No. You only pay while a sandbox is actively running. Once a sandbox is paused, killed or times out, compute billing stops immediately.
